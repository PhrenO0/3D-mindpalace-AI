3D 팀 · 내부 공유

내 방 사진/3D를 올리면 AI가 가구를 인식해
기억궁전 핫스팟을 자동으로 찍는다

지금까지는 내가 손으로 가구를 보고 좌표를 찍어 기억 지점을 만들었습니다. 이번에 그 과정을 AI(객체검출) + 레이캐스트(좌표 측정)로 자동화했습니다. Claude·외부 AI 서버 없이 브라우저 안에서 전부 돌고, 정적 서버/VM에서 스스로 작동합니다. 프로토타입

한 문장 원리

3D 핫스팟은 결국 “3D 좌표 하나(x,y,z)”일 뿐.
모든 작업은 “화면에 보이는 저 소파가 공간 어디에 있는가”를 알아내는 문제였다.

그 좌표를 알아내는 유일한 다리가 레이캐스트입니다 — 화면의 한 점에서 광선을 쏴, 처음 부딪힌 표면의 3D 좌표를 읽습니다. 손으로 할 땐 내가 눈으로 그 점을 찍었고, 자동화에선 AI 검출 박스가 그 점을 줍니다.

어떤 원리로 만드나 (파이프라인)

3D GLB가 입력일 때의 전체 흐름. 각 단계엔 “왜 그렇게 했는지” 이유가 붙어 있습니다.

① GLB 로드·정규화어떤 크기 방이든 같은 기준(가로7.2·바닥0)으로
→
② 관찰 지점 격자한 점이면 칸막이벽에 막힘 → 각 방 안에서 둘러봄
→
③ 다방향 렌더각 지점 4방향을 이미지로 캡처
→
④ AI 객체검출개방어휘(OWL-ViT): 찾을 가구 단어만 검색
→
⑤ 레이캐스트박스 여러 점을 실제 형상에 쏴 정확한 3D 좌표
→
⑥ 합의·중복제거여러 각도에서 반복 검출된 것만 채택(유령 제거)
→
⑦ 개념 매핑·마커규칙으로 조선 개념 배정 → 3D 마커 + JSON

핵심은 “화면점을 누가 주느냐”

레이캐스트 공식은 늘 같고, 자동화 단계는 ‘화면의 어느 점을 쏠지 누가 정하나’로만 갈립니다.

방법화면점 제공깊이정확도
① 손 (room-03)내가 눈으로 클릭실제 레이캐스트정확하지만 수동
② 2D 사진 스캐너AI 검출 박스 + 깊이추정AI가 추정대략적(2.5D)
③ 3D GLB 스캐너AI 검출 박스 + 실제 레이캐스트실제 측정정확 ★

작업물 · 결과

두 스캐너 모두 결과를 JSON으로 내보내며, 기존 방 시스템의 ROOM_HOTSPOTS 구조와 호환됩니다(3D 좌표 포함).

v2 — Azure 검출 & occlusion 해결

하이브리드: 인식=Azure · 위치=클라이언트

검출은 거대 학습된 Azure AI Vision이, 정확한 3D 좌표는 형상이 손에 있는 클라이언트 레이캐스트가 맡는다. (키는 백엔드 프록시로 보호, 없으면 브라우저 폴백)

가구브라우저 OWL-ViTAzure AI Vision
의자/식탁/싱크대/TV/소파14~35% (노이즈) 84 / 73 / 69 / 59 / 56%
occlusion 해결 — 표면 말고 "광선 교차점"

문틈 너머 가구는 광선이 중간 벽에 먼저 맞아 마커가 벽에 박혔다. → 표면을 맞히지 말고 여러 시점 광선이 수렴하는 점을 삼각측량하면 가림과 무관하게 진짜 위치가 나온다. 같은 사물 묶기도 표면이 아닌 광선끼리 수렴으로 판정. 실측: 의자가 6개 광선으로 정확히 수렴.

지금 상태 (솔직하게)

✅ 되는 것 (검증됨)

  • 광화문 지도·한옥·GPS마커·방 핫스팟이 서버 없이 더블클릭으로 동작
  • 스캐너 end-to-end: 로드→스캔→검출→3D좌표→마커→JSON
  • Azure 검출 압도적(의자 84%, 식탁 73% …) — 폴백 OWL-ViT와 차원 다름
  • occlusion 해결 — 다시점 광선 삼각측량(의자 6광선 수렴 확인)
  • 자동 테스트 8개 통과

⚠️ 아직 불안정 (개선 중)

  • Azure 라벨 혼동 — 합성 렌더에서 침대를 "식탁"으로 오인식 등 (삼각측량은 그 사물에 정확히 박지만 개념 매핑이 틀어짐)
  • 사물당 광선 부족 — 삼각측량엔 2시점↑ 필요하나 Azure 무료티어 분당 20콜 제한
  • 닫힌 셸형 분위기 스캔은 인식·조망 약함
  • 다지점 추론이라 저사양에서 20~30초
